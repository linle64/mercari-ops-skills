# Mercari 运营从零搭建（给接手 agent 的向导）

你接手了一个想做 Mercari 转卖、但完全不懂技术细节的用户。本技能带你把整套系统搭起来。原则：**能你做的都你做，只把「输密码、批准、掏钱」三类事留给用户**；每一步做完当场验收，不要攒到最后一起爆雷。

先通读 mercari-ops 总纲，再按下面阶段推进。任何一步卡住，先查本技能的 references 和各分技能，不要让用户去研究技术问题。

## 阶段 0：访谈（一次问完，别挤牙膏）

只问这些，每题给默认建议，用户不答就按默认走：

1. **几个 Mercari 账号？** 默认 1 个起步（单号也能跑全流程），有第二个再按双号分工（A 号拼多多线／B 号淘宝线）。
2. **卖什么品类？** 没有答案就建议先从一个垂直小品类试点（如装饰腰带），跑通再扩。
3. **货源走哪边？** 淘宝／拼多多／1688，可多选；对应账号在哪个浏览器登录由你安排（Chrome＝拼多多线、Brave＝淘宝线是已验证的分工）。
4. **执行机是哪台？** 需要一台能常开的 Mac（执行机）跑浏览器和桌面自动化。agent 本身在云端 VM 时，走 SSH+Tailscale 通道（见 references/ssh-tailscale.md）；agent 就在执行机本地时跳过通道阶段。
5. **发布授权？** 新手默认：**全部先存草稿、人工看过再发布**。等跑顺了，用户可以把某个品类改成直接发布（在 mercari-ops 里记下授权范围）。

把答案写成一份 `config.md` 放在用户的工作区（账号代称、浏览器分工、品类、定价带、授权范围），以后所有技能以它为准。**config 只存代称和分工，不存任何密码、cookie、账号 ID 以外的敏感值**——账号 ID 也只在用户本地 config 里有，不要外传。

## 阶段 1：脚手架

建目录（路径按用户环境定，结构照此）：

```
<工作区>/
  hidden_files/     # 台账与运行日志：pool.json、pool_pdd.json、candidates*.json、drafts.json、listed.json
  tools/            # 本地脚本（上架、取图、巡逻、消息发送）
  images/           # 上架图片的中转（本机侧对应桌面固定图片文件夹）
```

- 台账初始文件从本仓库 `templates/ledger/` 复制，字段口径见 mercari-ledger。
- 执行机桌面建固定图片文件夹（如 `mercari-images`），上架图片只许进这里（见 mercari-listing 的 image-sourcing）。

## 阶段 2：通道（agent 在云端时才需要）

按 `references/ssh-tailscale.md` 搭：Tailscale 组网 → SSH 密钥与 config → agent-desktop 安装与权限 → 桥脚本常驻。搭完跑里面的连通性验收，全过才进下一阶段。

## 阶段 3：克隆浏览器

按 `references/clone-browsers.md` 建 Chrome／Brave 的 CDP 克隆。**登录必须用户本人完成**：你把克隆窗口打开、停在登录页，请用户自己输账号密码（密码不经过你、不进聊天、不落任何文件）。用户登完，你逐个验收：Mercari mypage 显示已登录、货源平台能打开商品页。

## 阶段 4：定时任务

从本仓库 `templates/cron/` 装五个任务（正文是模板，把路径和账号代称换成 config 里的值）：

| 任务 | 节奏 | 对应技能 |
|---|---|---|
| 每周选品 | 周日上午 | mercari-select |
| 候选池水位守卫 | 每日傍晚（上架前） | mercari-select |
| 每日上架 | 每日傍晚 | mercari-listing |
| 评论巡逻 ×2 | 每日午间、晚间 | mercari-comments |
| 看板／对账刷新 | 每日早晨（可选） | mercari-ledger |

**先手动跑一轮验证再启用定时**；第一周建议全部任务只产出草稿和报告、不自动发布。

## 阶段 5：试跑验收（搭好的标准）

拿一件真实候选走完全程，你操作、用户只看结果：

- [ ] 选品过三道闸并入池（mercari-select）
- [ ] 取图落地图片文件夹、逐张核款通过（image-sourcing）
- [ ] 文字包按账号规范写好（copywriting）
- [ ] 克隆里建成草稿，类目／状態／特徴／配送都对（publish-flow）
- [ ] 草稿登记进 drafts.json，备份习惯就位（mercari-ledger）
- [ ] 用户看过草稿并点头 → 才把发布授权按阶段 0 的约定打开

全过＝搭建完成。把验收结果和 config 一起留在工作区，并告诉用户日常他只需要做三件事：**补货时决定买什么、看报告批准对外消息、定期看一眼台账**。其余巡逻、上架、对账由定时任务和你接管。

## 红线（搭建期同样适用）

- 密码、验证码永远用户本人输入，你不代输、不经手、不保存。
- 没验收过的通道不要跑批量任务；Mercari 拦截纪律见 mercari-ops。
- 授权范围只按 config 里写的执行，用户没明确给的品类一律先草稿。
