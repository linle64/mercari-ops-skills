# 环境与通道定版（操作 Mercari 前必读）

本文件是 Mercari 运营的操作环境定版，全部来自实证教训：每条都是踩过坑之后定的。

## 通道分工

- 远程 Mac 操作走 **SSH＋桌面自动化工具（如 agent-desktop）**。经 SSH 调用桌面自动化时，注意补齐登录 shell 的 PATH（npm/node 往往不在非交互 SSH 的 PATH 里）。
- **录屏权限归属坑**：macOS 按「启动它的应用」归属录屏权限。经 SSH 拉起的自动化进程，其录屏 TCC 状态会被钉死为 denied，哪怕系统设置里开关是开的。定版解法：杀掉旧的常驻进程，改由**图形会话里的桥脚本**（终端里常驻轮询 job 文件）拉起新进程，截图与物理操作一律经桥下 job 执行，不要从 SSH 直接调。
- 桥没在跑（Mac 重启／终端关闭）时，先请人在 Mac 终端重跑桥命令，不要自己从 SSH 拉。
- 自动化窗口尽量放在扩展显示器上，不挤主屏抢焦点。

## CDP 克隆浏览器（建草稿／发布的主通道）

- 分工：Chrome 克隆（端口 9223）＝A 号；Brave 克隆（端口 9224）＝B 号。
- **克隆必须经 GUI 会话用 LaunchServices 启动**（`open -na "<浏览器>" --args --user-data-dir=~/cdp-* --remote-debugging-port=...`）。经 SSH 直拉的克隆拿不到 macOS Keychain，Cookies 会被清零、登录态全失。
- 克隆 profile 要带齐：Cookies（sqlite 热备）、Preferences、Local Storage、IndexedDB、Session Storage、Device Bound Sessions、WebStorage＋根目录 Local State，只复制 Cookies 会显示未登录。
- **不要用「整库覆盖式」的克隆刷新脚本**——会冲掉克隆内自己登录的会话。要刷新登录态就在克隆里重新登录。
- 完事关克隆：按 user-data-dir 精确 pkill，别误伤原浏览器。
- 导航用 `open -a "<浏览器>" '<URL>'`（桌面自动化的地址栏回车不提交导航）。**osascript 经 SSH 会挂死，禁试。**
- 克隆里遇只有密码框的再认证页：点密码输入框下方显示的邮箱条目（自动填充候选）填入密码，前提是克隆窗口真实前台化＋页面有焦点。

## 文件读取的坑

- **Chrome 克隆读不到 ~/Desktop 下文件的“内容”**（元数据在、FileReader 超时，疑 macOS 隐私限制）；Brave 克隆不受影响。定版绕法：A 号传图前先把图拷到 `/tmp` 暂存再上传，用后删除，原图仍留图片文件夹。
- 同理，克隆经 CDP 程序化读 ~/Documents 文件内容也会失败，先拷 /tmp。

## 文件选择器（NSOpenPanel）

- 窗口必须**全宽**：窗口太窄时 sheet 大半落在框外，行与按钮不进可控元素树。平铺半屏只够行出现、按钮仍在框外——必须全屏宽。
- sheet 面快照的 ref 点行可能恒报 STALE_REF（进程短名不一致）；解法：取**整窗全量快照**，用其中文件行的 ref 点击（AXOpen 语义直接选文件）。
- 键盘法备选：打开选择器（默认「最近使用」含图片文件夹全部文件）→ activate 浏览器 → 方向键选行（无选中态时 ↓ 第一下选首行；按日期分组时截图核对蓝高亮的文件名）→ Return。每张重开重选。
- 选择器枚举不到行时靠重开选择器刷新，**不许把图片临时放桌面根目录当中转**。

## Mercari 风控与拦截

- 风控大概率针对自动化会话本身：自动化浏览器与实时窗口共用同一出口 IP 与登录会话时，会话被刷热后实时窗口同样会被拦。
- 报拦截的纪律：先用新开的实时窗口同页复核，复核也拦才下结论；报告时说明复核环境；最终判定只认本人在本地网络下用自己设备打开的结果。
- 同一页面被拦后**当天不要反复重试刷页**，先冷却。
