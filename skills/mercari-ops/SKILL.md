# Mercari 双号运营总纲（技能库入口）

这是一套在真实运营中打磨出来的 Mercari 双账号转卖流程。本技能是总纲：先在这里对齐战略、账号分工和授权边界，再按任务去读对应分技能。

台账与运行日志放在自己的工作区目录（下文称 `hidden_files/`）：候选池、草稿台账、在售台账都在那里。脚本放在本地 `tools/` 目录，索引见文末。

**还没搭过这套系统？** 先走 mercari-setup 技能从零搭建（通道、克隆浏览器、台账、定时任务、试跑验收），搭好后再回本总纲做日常运营。

## 全流程地图

| 环节 | 分技能 | 建议节奏 | 产出 |
|---|---|---|---|
| 选品筛查 | mercari-select | 每周一轮选品＋每日池水位守卫 | pool.json / pool_pdd.json 候选池 |
| 取图核款＋文案 | mercari-listing（references/image-sourcing、copywriting） | — | 上架包（图片＋标题＋说明＋价格） |
| 建草稿／发布 | mercari-listing（references/publish-flow） | 每日傍晚一轮 | 草稿或发布＋listed.json 登记 |
| 评论巡逻 | mercari-comments | 每日午间、晚间两轮 | 回复草稿（等人工确认才发） |
| 取引消息 | mercari-transaction-messages | — | 发送＋API 层核实 |
| 台账对账 | mercari-ledger | 每日轻量＋每周全量 | listed.json / drafts.json、删除评审 |

## 战略

- **只发已购现货（含在途）；未购候选只保留候选资格、不发布。** 自动补位只在现货范围内顺延。这样避免卖出后无货可发、被迫取消订单伤账号。
- 选一个验证过的垂直品类深耕（本库的实证品类是 y2k 装饰扣头腰带）；定价带按品类毛利模型设定并保持统一；素材标注全店统一口径。
- 节奏：每周上新一批＋全店 bump；7 天零浏览改标题／降价；30 天零成交进下架评审。

## 双账号分工（铁律）

- **A 号**＝Chrome，专做**拼多多**货源。标题**不加前缀**，标题＋说明文**另写一版**。
- **B 号**＝Brave，做**淘宝**款。标题按规律加前缀。
- 两号**不上同款**，各号独立定价。两号文案雷同既伤观感也容易被平台关联，分开写是硬规矩。

## 授权边界（最重要）

- 明确授权的品类可以由 agent 直接发布（本库实证：腰带上架不用人工审查、直接点「出品する」）。**下架不在任何默认授权内**，须单独指令。
- 其余一切对外动作（评论回复、取引消息、改价、降价请求答复）先展示全文／方案，等人工明确确认后再执行。
- **对外口径**：绝不提商品来自海外／国际运输在途；只说「准备中、备好即发」。

## 硬规则总表（细节在各分技能）

1. **侵权硬线**：一眼认出是设计师品牌原款的仿款一律跳过，不入池、不上架。
2. **筛查前置**：去重、侵权目视、单 SKU 图组三道闸在入池／做文字包阶段完成，不拖到建草稿当天；当日候选不合格，同次运行自动顺延下一候选（最多 3 件，现货范围内）。
3. **图片只进一个固定文件夹**（如桌面的 `mercari-images`），任何中转副本也不许散落在桌面根目录。
4. **逐张核款才叫校验**：上架图必须与商品主图逐张视觉比对（扣头形状、尾扣、带身宽窄），只查数量／格式不算校验。1688「同款」图默认不可信（同链接常混多 SKU）。
5. **台账状态以实时核查为准**：pool 的 status 会滞后于 drafts/listed，取候选前必须以 drafts.json＋listed.json 交叉核对。
6. **拦截判定纪律**：自动化会话报 Mercari 拦截时，先用新开的实时窗口同页复核；自动化浏览器与实时窗口可能共用出口 IP 和登录态，一边被拦不等于账号被封；同一页面被拦后当天不要反复重试，先冷却。最终判定只认本人在本地网络下用自己设备打开的结果。
7. **有评论的商品先不删**，删除评审时单独列出等人工决定。

## 环境与通道

操作走 SSH＋桌面自动化桥＋CDP 克隆浏览器。克隆分工：Chrome 克隆（端口 9223）＝A 号，Brave 克隆（端口 9224）＝B 号。启动、传图、文件选择器、录屏权限等全部定版打法见 `references/environment.md`——**动手操作前必读**。

## 脚本索引（本地 `tools/` 目录，按用途自备）
