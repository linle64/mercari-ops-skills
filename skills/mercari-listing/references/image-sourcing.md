# 取图与核款定版

取图与核款留在**本机（本人登录态）**做——云端浏览器打开货源平台长期不稳定（登录墙、短信验证、机房 IP 风控），不要把取图搬去云端。靠批量纪律提速，不靠换环境。

## 落点铁律

- 上架图片的落点只有固定的图片文件夹一处（如桌面 `mercari-images/`），**任何中转／临时副本也不许放桌面根目录**。
- 例外只有传图通道：A 号（Chrome 克隆）读不到桌面文件内容，传图前把图拷到 `/tmp` 暂存，用后删除——这是上传暂存，不是图片落点，原图仍在图片文件夹。

## 淘宝取图正路：无障碍树 find 拼原图直链

1. 在本机 Chrome 打开淘宝商品页，用桌面自动化的 `find --role image`（按 role 全树搜）列出全部图片元素——浅层 snapshot 搜不到图库图，必须全树搜。
2. 每个图库图的 name 就是 alicdn 文件名（含卖家 ID）。拼原图：`https://img.alicdn.com/imgextra/i{1..4}/<卖家ID>/<文件名去后缀>`，逐 shard 试（404 换下一个），下到的是真原图（JPEG 文件头、体积明显大于转码图）。
3. 顺序：图名按 bounds 的 y 坐标排（缩略图条自上而下＝图库顺序），主图大图元素同名可交叉确认。详情区图（height=0、y 在折叠线）是懒加载占位，同名一并收集，去重后即详情图。
4. 不要试 mtop 官方 API 直连（撞风控盾）；不要用 curl 直取带 `_.webp` 的链接（alicdn 会按请求特征转码成 WebP，不是原图）。

淘宝页面注意：桌面商品页直接拼 `item.taobao.com/item.htm?id=` 打开常是精简模板；从店铺页点商品进入（带 spm 参数）才渲染完整模板。店铺目录页 `shop<id>.world.taobao.com/category.htm` 由商品页「进店」直达，是批量回填同店 ID 的正路。淘宝识图（首页相机「搜同款」）可作找同款第一步。

## 拼多多取图

- 克隆 Chrome 登录态可直达订单页 `mobile.yangkeduo.com/orders.html`；订单详情页 HTML 里正则 `goods_id["']?\s*[:=]\s*["']?(\d{6,})` 提取 goods_id。
- 商品页大图（≥750px）DOM 提取后去掉 `?` 参数即原图，本机 fetch 直下 pddpic。
- 拼多多账号级限流（「系统繁忙」）时停手，等隔日冷却或用 App 查，不要换浏览器硬刷。

## 1688 备选

淘宝图库取不到时去 1688 找同源商品（同工厂货），其「铺货素材预览」给无后缀原图直链（cbu01.alicdn.com），可直接下载。但 1688「同款」图默认混多个 SKU，核款要求更严（见下）。

## 逐张核款（校验的定义）

- 上架包每张图必须与商品主图**逐张视觉比对**：扣头形状、尾扣、带身宽窄，确认同一款才可用；混款图一律剔除。
- 图组须能组成：单款全图＋扣头特写＋尾扣。集合平铺图、多 SKU 混拍不合格。
- 报告里说「已校验」必须指这里的内容核对；只查数量／格式不许叫校验。
