# Mercari 上架全流程

一条 listing 的完整链条：**取图 → 核款 → 文案 → 发布（或建草稿）→ 终检 → 台账登记**。

## 分工与定价

- A 号（Chrome 克隆 9223）＝拼多多货源；B 号（Brave 克隆 9224）＝淘宝货源。两号不上同款。
- 定价带按品类毛利模型统一设定；素材标注全店统一（如腰带统一标注フェイクレザー）。
- 发布节奏与现货优先规则见 mercari-ops；未购候选不发布。

## 四个阶段

1. **取图与核款** → `references/image-sourcing.md`
   在本机（本人登录态）取图：淘宝走无障碍树 find 拼原图直链，拼多多走订单／商品页大图。图片只落固定的图片文件夹。逐张与主图核款（扣头形状、尾扣、带身宽窄）才算校验完成。
2. **文案** → `references/copywriting.md`
   标题／说明／价格先做成文字包。B 号标题加前缀、A 号不加且另写一版；首图加发货角标；说明文写清尺寸与发货口径。
3. **发布** → `references/publish-flow.md`
   CDP 克隆里用两段式脚本跑完：图片、类目、状態、特徴、配送、价格，最后发布或存草稿。获授权的品类可直接发布；发布后到商品页实测三项特徴在位才算完。
4. **登记**：把 m 编号、账号、价格、货源 ID 写进 `listed.json`（发布）或 `drafts.json`（草稿），改前备份。运行日志写 `hidden_files/run-<日期>-*.md`。

## 改价与设置变更

- 改价、改发货日数、改説明文：走商品编辑页 `/sell/edit/<m编号>`，保存按钮是 **「変更する」**。改完到商品页复核实际显示值与台账同步。
- 改「発送までの日数」为 1~2 日的当日发货件：说明文换当日发货句、首图重加「当日発送」角标，三件套一起改。
- 降价请求（値下げ依頼）不擅自答应，列入报告等人工决定。

## 每日上架轮次

- 一个会话跑完当天全部件：先以 drafts/listed 交叉核对取现货候选（pool status 不可信），不合格自动顺延（最多 3 件，现货范围内）。
- 对账轻量化：每日只查下書き一覧消失情况；全量出品中对账只在固定日或人工回报已发布时做（见 mercari-ledger）。
- 环境受阻（机器离线、克隆登录态失效、Mercari 拦截）时按 mercari-ops 的拦截纪律处理并报告，不空跑硬刷。

## 红线

- 图组混款、侵权款不许上架（见 mercari-select 三道闸）；核款没过就停，不要「先发了再说」。
- 发布前终检以 finish 脚本的判据为准；已知主流程脚本的配送切片判据有误报，配送判据看 finish 段。
- CDP 求值每次导航会丢进行中表单的文字与图片；查进行中表单一律用不导航的直连脚本。
