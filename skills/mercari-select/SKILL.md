# Mercari 选品与筛查

选品的目标是给候选池持续补充「在 Mercari 上真有人卖得掉、且不踩侵权」的货。

## 数据文件（工作区 `hidden_files/`）

- `pool.json`：淘宝线候选池；`pool_pdd.json`：拼多多线候选池
- `candidates.json` / `candidates_pdd.json`：选品原始候选
- `drafts.json` / `listed.json`：已建草稿／已上架台账（去重核对以这两份为准）
- 改任何 JSON 前先备份（沿用 `.bak-<日期>-<轮次>` 的命名习惯）

## 选品依据

- **Mercari 侧只认别的卖家已售实证**：看同款／同类在 Mercari 的已售记录判断能不能走量，不凭货源平台销量或感觉推断。可以维护一个「走量商家看板」长期跟踪卖得动的卖家。
- **只留无品牌款**。没有实查到的链接就标「搜索」，不编假链接。
- 货源双线：淘宝（B 号）与拼多多（A 号）。拼多多登录态在本机浏览器，过期须本人重登，agent 不代登。拼多多网页版有账号级限流（「系统繁忙」），换浏览器、重登都没用，只能等隔日冷却或在 App 查。

## 筛查前置三道闸（入池／做文字包前必须过完）

1. **去重**：对 drafts.json＋listed.json 查源平台商品 ID，已建草稿或已上架的同款直接剔除。注意 pool 的 status 会滞后（已上架仍标 pooled 的情况出现过），以 drafts/listed 交叉核对为准。
2. **侵权目视**：看主图与图库，一眼认出是设计师品牌原款或其代表性图案的仿款，一律 dropped 并记名。典型例子：十字花图案（Chrome Hearts 式）、匕首形尾扣（先锋设计师品牌打版）、整组图片压着品牌字样卡片的图组。
3. **单 SKU 图组**：图库必须能组成单款全图＋扣头特写＋尾扣；集合平铺图组、多 SKU 混拍不算合格。1688「同款」链接默认混款，逐张核对（见 mercari-listing 的取图核款）。

## 入池与补位

- 过闸的候选写入对应 pool 文件，注明货源、源链接 ID、价格、拟上账号。
- **现货优先**：未购候选只入池保留资格，不进入发布；发布与自动补位只在已购现货（含在途）范围内进行。
- 当日候选在任一环节被判不合格，同次运行自动顺延下一候选，最多顺延 3 件，把合格件做完才收工（环境受阻除外，仍须报告）。

## 定时轮次（建议节奏）

- **每周选品**：全量选品，产出 select 日志。
- **每日池水位守卫**：检查候选池水位与筛查积压，不足时报告。
- 每轮日志写进 `hidden_files/`，命名沿用 `run-*/select-*/pool-guard-*` 格式。

## 报告口径

- 报数字必须回源页原文：已售件数、价格等从 Mercari／货源页实查，不凭记忆。
- 报告里说「已校验」必须指内容核对（过三道闸），只查了数量或格式不许叫校验。
